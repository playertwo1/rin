# Regras para documentação do RIN

As regras da raiz continuam válidas. Este arquivo se aplica a `docs/`.

- Diferencie requisito, proposta, decisão aceita e resultado observado.
- Nunca altere documentos históricos para fazê-los parecer atuais.
- Mantenha IDs de fases, tarefas, requisitos e dependências estáveis.
- Mudança de escopo exige justificativa e rastreabilidade; atualizar status não substitui evidência.
- Não chame schema de publicado nem endpoint de disponível sem fonte e teste correspondentes.
- Ao alterar uma fase, revise suas dependências, a matriz de requisitos e o índice ROADMAP.
- Valide links locais e caminhos. Caminho futuro deve estar rotulado como previsto.
- Use exemplos sintéticos identificados; não inclua dados privados nem credenciais.
- Documentação concluída não significa implementação concluída.
